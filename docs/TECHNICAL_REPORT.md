# Jev Gateway: local technical findings at the Day 6 checkpoint

**Status:** local draft, 2026-11-01 America/Toronto. The gateway implementation is substantial; the original comparative research question remains unanswered because model answers and NVIDIA measurements are missing. Figures and numbers below refer only to the cited raw records.

## Problem and system

The project asks whether a three-tier gateway can retain answer quality while reducing expensive generation, and what routing, verification, and caching add to latency and cost. The tiers are a small and medium native Ollama model, plus a configured frontier API. `model=auto` asks Jev to select an eligible tier and can use a trained DistilBERT fallback only when a compatible artifact is present. Fixed and seeded-random baselines, a prompted small-model router, a local Strands Decider adapter, Jev choice, Jev success thresholds, and an observed hindsight oracle provide comparison paths. The oracle is an offline reference, never an online policy.

The optional execution paths are route-first, a small-to-medium-to-frontier verification cascade, and a route-then-verify hybrid. The verifier judges an answer against its request and instructions without receiving the benchmark reference. The semantic cache scopes entries by instructions, conversation, namespace, generation identity, model/policy identity, and embedding revision. A similarity hit alone is not verified reuse; the verified mode asks Jev whether a scoped candidate applies. The gateway keeps a cumulative cost/budget ledger and rejects unavailable or ineligible choices. Process-level Prometheus metrics, structured traces, Compose, kind, Locust schedules, and a 50-case synthetic CI regression set cover operations.

## Evaluation design and held-out gate

Pinned source preparation selected 2,500 unique prompt IDs: 1,100 GSM8K math, 1,000 MMLU multiple choice, and 400 sanitized MBPP code tasks. Related exact normalized-text groups stay in one project split: 1,500 train, 500 validation, 500 test. The split index is committed; private prompt text and references are ignored. Scoring is task specific, and code evaluation uses a bounded container. The grouping does not prove semantic deduplication. A result record carries backend/model, settings fingerprint, attempts, outcome, timings, usage, cost status, and real versus mocked origin.

The only real generation file currently contains two validation attempts for one prompt: small and medium both returned `backend_error`, with no answer, usage, or charge. Frontier is unconfigured. The [raw freeze audit](../evidence/day6/freeze-audit-20261101.json) counts **zero scored train or validation prompts** for all three tiers and lists all required model/router freeze fields as missing. It found no test result in the inspected file. Existing commands deliberately exclude the held-out split. The project cannot train a defensible success router, select thresholds from validation, freeze compatible generation identities, or run final test comparisons yet. No held-out test claim is made.

The existing validation replay enumerates ten router policies but has zero scored comparisons. Fixed small/medium each match one failed backend result; the frontier and model-based policies have no scored observations. The [composed-system audit](../evidence/day6/system-audit-20261101.json) also shows zero real observations in disabled, similarity-only, and verified cache modes. The Day 4 12-case cache set is hand-authored validation material for protocol checks, not a held-out performance estimate. It includes true paraphrases, answer-changing near misses, and unrelated queries grouped by seed. No cache threshold or harmful-reuse rate is measured. The cascade and hybrid paths are tested with fixtures, not real held-out answers.

## Calibration, timing, and uncertainty

The calibration implementation defines binary **generator-success** as externally scored correctness for a specified generator, separate from the multiclass cheapest-successful-tier oracle label. It computes equal-width reliability bins, ECE, and appropriate binary or multiclass Brier scores when matching observations exist. The current saved calibration report has status `insufficient_data` and count zero. There is no reliability curve or interval to interpret.

One real Mac microbenchmark measured fixed and random **decision-only** functions: 10 warm-ups and 100 sequential measured calls per policy on arm64 CPU, with no model loaded, network, or generation. Always-small and always-medium p50/p95 were each 0.001583/0.001667 ms; seeded-random was 0.002188/0.002750 ms. The raw run is `runs/day3-routing-benchmark-e6f85069cc9d4bd3a5545766cb7dc0a6.json` (private). These microsecond values have timer/scheduling noise and say nothing about Jev, DistilBERT, or end-to-end latency. The Day 6 group-paired bootstrap helper defines a future uncertainty method but produces no empirical interval without matched real outcomes.

## Operations and reliability

The Day 5 ARM image passed a container health check. Prometheus scraped the Compose gateway, Grafana provisioned 14 panels, and all 17 configured PromQL expressions parsed. A controlled kind pod deletion during 40 `GET /v1/models` calls produced **39 HTTP 200** responses and one connection error over **4.8128 seconds**. That endpoint served catalog data, not inference. A short Locust wiring check made two requests in **1.884353 seconds**; both returned HTTP 502 because Ollama was unavailable. The intended ten-minute steady, two-minute spike, and one-hour soak inference runs were not completed. Jev outage/recovery was exercised with injected fixture responses, not a live provider failure. These checks establish local deployment and failure-reporting behavior, not model capacity.

## NVIDIA investigation and cost

The Day 6 Colab notebook and packaged tools pin a source archive hash, record GPU/runtime/model/config identities, generate a deterministic synthetic 32-prompt workload, save every bounded client request, and optionally collect a separate Nsight Systems trace. A candidate batch-token-budget change requires three successful compatible baseline files and an explicit falsifiable hypothesis. The repeated-run comparator requires alternating conditions and matching workload, arrival, concurrency, warm-up, timeout, and request count. It keeps failures, output lengths, throughput, latency, and before/after GPU snapshots. **No Colab runtime, vLLM server, GPU trace, candidate run, or speedup was observed.** The snapshots alone would not diagnose a kernel bottleneck.

The cost design distinguishes recorded charges, dated API estimates, modeled allocated GPU capacity, and unknown charges. It includes routing, verification, embeddings, candidate checks, retries, and rejected attempts. An unknown stage prevents a total-cost claim. Provisioned compute includes idle allocation; fewer requests on a reserved GPU do not imply a smaller bill. Because no successful generation/provider usage or dated applicable rate set exists, there is no measured quality/cost frontier or capacity estimate.

## Reproduce and limitations

The fresh package wheel installed with standard dependencies in a Python 3.14 temporary environment without CUDA. A clean local clone installed the `test` extra, passed **127 offline tests with one third-party warning**, and returned HTTP 200 from `/healthz` on loopback. Its `doctor` found unavailable native Ollama tiers and unconfigured frontier. Remote CI has not run. See [reproduction commands](DAY6_REPRO.md), [experiment protocol](DAY6_PROTOCOL.md), and the [coverage figure](../evidence/day6/pre-freeze-coverage-20261101.svg).

The major limitations are absent real model labels, trained artifact, Jev credentials/budget, local Ollama, embedding model/FAISS real checks, Colab GPU allocation, live inference load, final test evaluation, sourced rates, and real complete-request timings. The implemented comparisons and operational checks are useful infrastructure, but they do not establish the research hypothesis or NVIDIA optimization outcome. The next defensible step is to collect compatible train/validation answers across tiers, audit them, select and freeze policies, and only then use the held-out test. In parallel, run the controlled Colab baseline and profile before choosing one serving factor to change.
