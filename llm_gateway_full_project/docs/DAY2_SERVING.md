# Controlled serving baseline

Serving workloads are separate from quality collection. A workload pins tier, text and output cap, stopping rule, scheduled arrival interval, concurrency, warm-up count, cache state, backend placement, and declared cold/warm/unverified model condition. The runner records both scheduled and achieved client starts. Stream parsing records first visible text, not the first SSE event, and uses provider completion-token usage only if supplied. A sequential tier-quality run is not live routing performance. Cold and warm labels require environment evidence; the runner cannot force model residency.

Latency is measured at the client from request start to stream end. First-visible latency ends at the first nonempty text delta. Percentiles use nearest-rank over individual requests; success-only p50/p95 and all-observed p95 are separate, with errors counted. Throughput is completed non-warm-up requests divided by entire observed run wall time. The optional TPOT proxy is `(stream end − first visible text)/(provider completion tokens − 1)` for successful streams with at least two reported output tokens; it is not GPU decode time. An SSE event is not assumed to be a token. Character counts never become token counts, HTTP duration is not GPU execution, and stage percentiles are not summed.
